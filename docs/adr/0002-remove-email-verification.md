# 移除邮箱验证，注册即登录

**Status**: 已接受（本项目为 demo，接受其安全代价）

移除 `User.verifiedAt` 字段与整套注册邮箱验证流程（验证邮件、验证页、重发入口、登录硬门槛），注册成功即签发 Session。密码重置保留。

**Context**: 邮箱验证的价值在于证明"账号确实属于该邮箱的主人"，防抢注、防机器人批量注册、保证重置邮件可达。但本项目是演示项目，验证流程增加了注册摩擦与代码面（验证令牌的一个 purpose、两个页面、一条登录失败分支），收益用不上。

**Considered Options**:
- 保留验证、把 `verifiedAt` 换成布尔字段（被拒：信息只少不多，流程摩擦照旧）。
- 用 Token 表推导验证状态（被拒：令牌一次性消费且 24 小时过期，验证后无持久痕迹，推导不出来）。

**Consequences**:
- 注册不再证明邮箱所有权：存在抢注攻击窗口（攻击者可用他人邮箱注册并登录，真正主人需靠密码重置找回）。
- 密码重置邮件会发往从未确认过的地址；机器人可零成本批量注册。
- ADR-0001 失去意义（重置不再需要"蕴含验证"，因为没有验证状态可写）。
- 若未来要上线真实用户，应恢复邮箱验证或以其他手段（OAuth 等）建立邮箱归属证明。
