# 密码重置蕴含邮箱验证

**Status**: 已废弃（superseded by ADR-0002，而 ADR-0002 本身也已于 `a070113` 被推翻）——本决策描述的是「在存在邮箱验证的前提下，重置密码顺带把邮箱标记为已验证」。该行为在当前代码中**不存在**：`emailVerifiedAt` 只由邮箱验证流程（`consumeVerificationToken`）写入，密码重置不碰它。邮箱验证本身已被重新引入，所以本决策的「作用对象」又回来了，但决策没有被重新采纳。当前行为以 CONTEXT.md「reset」为准；是否恢复「重置蕴含验证」是一个**未决问题**。

账号可能处于"已注册但未验证邮箱"的状态，此时用户忘记密码。我们决定：密码重置成功的同时将邮箱标记为 verified。因为能收到重置邮件本身就证明了邮箱所有权——这与点击验证链接证明的是同一件事；若重置后仍要求单独验证，用户改完密码依然登录不了，闭环出现裂缝。

**Considered Options**: 重置只改密码、验证状态不变（被拒：制造"改了密码却进不了门"的死锁体验，且安全上并无增益）。

**Consequences**: `resetPassword` 会写 `verifiedAt`，读代码时不要误以为是笔误而"修复"掉。
